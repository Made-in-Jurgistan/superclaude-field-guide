How to Use This Guide

You do not need to read it all. Find your starting point below.

This guide is written for people who have never typed a SuperClaude command. Every technical word is explained the first time it appears, and again in the glossary. Experienced users can jump straight to the reference sections and recipes.

Choose Your Path

Brand new
Read Sections 1 to 3 in order. Then pick a recipe from Section 11. See page 4.
Using it daily
Keep Section 4 (commands) and Section 23 (pocket cards) open. See page 10.
Going deeper
Sections 7 to 10 explain modes, tools, flags and rules. See page 21.
Not a programmer
Research and business recipes (Section 18) need no coding at all. See page 48.

Labels You Will See

Two kinds of label appear throughout. The square ones tell you what a command does to your files. The round ones tell you how experienced you need to be. Every label carries a word as well as a color, so the guide reads correctly in black and white.

Section 01

What SuperClaude Is

A plain-language picture before any commands.

Claude Code is Anthropic's tool that lets Claude work directly on the files in a project folder: reading code, writing code and running commands. SuperClaude is a free add-on, made by an independent community, that gives Claude Code a set of ready-made working methods.

Without SuperClaude, you explain every time how you want Claude to approach a job. With it, you type a short command such as /sc:brainstorm and Claude follows a tried-and-tested procedure: it asks the right questions, involves the right expertise, uses the right tools and stops at sensible checkpoints so you stay in control.

Under the hood it is just text

SuperClaude is a collection of instruction files written in Markdown (a simple text format). Installing it copies those files into a hidden folder called ~/.claude/ in your home directory. It does not change which Claude model you use, your plan or your bill.

The Five Building Blocks

Think of the framework as a stack. You touch the top layer; everything below supports it.

Commands
The verbs. You type /sc:something to start a structured job such as planning, building or testing.
Specialists
The experts. Each command calls in the right "hat": security engineer, technical writer, architect.
Modes
The working style. Questioning when ideas are vague, compressed when space is tight, step-by-step for big jobs.
Helper tools
The instruments. Optional add-ons that read official docs, drive a browser, search the web or remember sessions.
House rules and flags
The standing policy and the fine-tuning dials that govern everything above.

What Happens When You Type a Command

Youdescribe a goal or type a command
Commanddecides the kind of job
Specialistsbring the right expertise
Toolsfetch docs, test, search
Resulta plan, a report or code

A Simple Way to Picture It

Imagine hiring a small consulting firm for each job. The command is the type of engagement: a design review, a build, a bug hunt. The specialists are the consultants who turn up. The helper tools are their reference books and instruments. The house rules are the firm's policies: check your work, never fake a passing test, never leave a job half done.

The Single Most Important Idea

Many commands stop on purpose. A planning command produces a plan and waits; it will not quietly start changing your code. That is a safety feature. Section 5, the safety ladder (page 17), shows exactly which commands look, which plan and which change files.

What SuperClaude Is Not

  • It is not an Anthropic product, and Anthropic does not support it.
  • It is not a separate app. It only works inside Claude Code.
  • It is not magic. It is good working methods, written down. You still review what Claude produces.

Install and Set Up

From nothing to a working installation, then optional extras.

Installation takes about five minutes. The core needs only Python; the helper tools are optional and can be added later, one at a time.

Install in Four Steps

Install the Package (Terminal)

terminalpipx install superclaude      # recommended
# or, if you don't have pipx:
pip install superclaude

Copy the Commands and Specialists Into Claude Code (Terminal)

terminalsuperclaude install           # 30 commands + 20 specialist files

Commands go to ~/.claude/commands/sc/, specialists to ~/.claude/agents/.

Check the Installation (Terminal)

terminalsuperclaude install --list    # shows every command and specialist
superclaude doctor            # health check
superclaude version           # should print 4.3.0

Restart Claude Code Completely, Then Test It (Claude Code)

claude code/sc:help

If a table of commands appears, you are ready. If not, see page 51.

Adding Helper Tools (Optional)

Helper tools make some commands much better: official documentation lookup, real browser testing, web research and memory between sessions. Every command still works without them. The superclaude mcp command installs them for you.

terminalsuperclaude mcp --list                          # see what is available and installed
superclaude mcp                                 # choose interactively
superclaude mcp --servers context7 --servers sequential-thinking
superclaude mcp --servers tavily --dry-run      # preview without installing
superclaude mcp --scope project                 # this project only (default: user)

Three tools need a free or paid key from their provider. The installer asks for it, or you can set it in your environment first:

ToolKey nameGet it from
Tavily (web search)TAVILY_API_KEYapp.tavily.com
Magic (UI components)TWENTY_FIRST_API_KEY21st.dev
Morphllm (bulk edits)MORPH_API_KEYmorphllm.com
Where to start

Begin with Context7 and Sequential: no keys, big improvement. Add Serena when you want memory between sessions, and Tavily when you start using /sc:research.

The AIRIS Gateway (Advanced)

The installer also offers the AIRIS MCP Gateway, which bundles more than 60 tools, including Airis Agent and MindBase, behind one connection. It needs Docker running on your machine.

terminalsuperclaude mcp --servers airis-mcp-gateway

Updating

terminalpipx upgrade superclaude      # or: pip install --upgrade superclaude
superclaude update            # overwrite the old command files with the new ones
Running install again does not update

superclaude install skips any file that already exists, so after an upgrade it silently keeps the old commands. Use superclaude update (the same as superclaude install --force). Then restart Claude Code.

Optional: The Confidence-Check Skill

The /sc:agent controller can use a small "confidence check" skill that scores how sure Claude is before it starts building.

terminalsuperclaude install-skill confidence-check

Windows Notes

  • Use pip or pipx in PowerShell. The install.sh script is for macOS and Linux (or Git Bash).
  • If superclaude is "not recognized", run python -m superclaude install instead, or add Python's Scripts folder to your PATH.
  • With several Python versions, pick one explicitly: py -3.12 -m pip install superclaude.

Uninstalling

terminalpipx uninstall superclaude                 # or: pip uninstall superclaude
rm -rf ~/.claude/commands/sc               # removes the 30 commands
claude mcp remove <tool-name>              # for each helper tool you added
Remove agents one by one

The specialists live in ~/.claude/agents/ alongside any agents of your own. Delete only the SuperClaude files (their names are listed on page 18, plus deep-research.md) rather than the whole folder.

Section 03

Your First Session

A guided twenty-minute walk-through you can follow along.

This walk-through takes about twenty minutes and is completely safe: nothing changes your files until step 5, and even then you approve every change. Open Claude Code in any project folder, ideally one tracked by git.

Open Your Project and Load Context

claude code/sc:load

Claude reads the project. On a first run there is nothing saved yet, which is fine.

Not Sure What to Do? Ask

claude code/sc:recommend "I want to understand this project and then fix a small bug" --expertise beginner

You get a suggested sequence of commands with an explanation of each. Notice it changes nothing.

Get a Tour of the Code

claude code/sc:analyze . --focus architecture --depth quick
/sc:explain src --level basic

The first gives a structured overview; the second explains it in everyday language.

Diagnose Something, Without Fixing It

claude code/sc:troubleshoot "describe a small problem you know about" --type bug --trace

You receive a likely cause and ranked options. Still nothing has changed.

Apply a Fix, With Your Approval

claude code/sc:troubleshoot "the same description" --type bug --fix
/sc:test

Claude asks before applying anything risky, then runs your tests.

Commit and Save

claude code/sc:git commit --smart-commit
/sc:save --checkpoint

A tidy commit message is written for you, and the session is saved so tomorrow's /sc:load picks up here.

You can always just talk

Commands are shortcuts, not a requirement. Type /sc:pm followed by a goal in plain English, for example /sc:pm "add a dark mode toggle to the settings page", and the project-manager specialist works out which steps and experts are needed.

Nothing runs on its own

Some SuperClaude files describe /sc:pm and /sc:agent as starting automatically. That applies only to the future plugin edition. With today's pip or pipx install, nothing happens until you type a command.

A Routine Worth Keeping

WhenTypeWhy
Start of a session/sc:loadRestore yesterday's context
Unsure what to do/sc:recommend "…"Get a suggested path
Every 30 minutes, and before risky steps/sc:save --checkpointA restore point
Before calling it done/sc:reflect --type completionCatch anything missed
End of a session/sc:save --type allKeep everything for next time

The 30 Commands

What each slash command does, when to use it and what comes next.

There are 30 commands. You will use about eight of them most days. They are grouped below by what you are trying to do, and every card shows the same five things: what it does, a label for its effect on your files, the full syntax, a realistic example and the usual next step.

Short and long names

Some older pages write /implement instead of /sc:implement. They are the same command. Because the files install into a folder called sc, Claude Code shows them with the sc: prefix. Always type the /sc: form.

The Safety Ladder

Every command sits on one rung of this ladder. The higher the rung on the page, the less it can touch. If you are nervous, stay on the first two rungs: they cannot change a single file.

The Seven Modes

Working styles that switch on by themselves, or when you ask.

Modes are working styles rather than jobs. They decide how Claude behaves while a command runs: asking questions, showing its reasoning, compressing its answers. They switch on by themselves when the situation calls for it, and you can force one with a flag.

Brainstorming
Switch on: --brainstorm
Kicks in when: Vague requests: "maybe", "thinking about", "not sure".
What changes: Asks questions instead of assuming, then writes a requirements brief.
Introspection
Switch on: --introspect
Kicks in when: Error recovery, "why did you do that?", tricky decisions.
What changes: Shows its reasoning step by step with small markers, so you can see how it decided.
Deep Research
Switch on: /sc:research
Kicks in when: Research questions and anything past the model's knowledge cutoff.
What changes: Plans an investigation, searches in parallel, cites sources and states confidence.
Task Management
Switch on: --task-manage
Kicks in when: Jobs with more than three steps, or touching more than two folders or three files.
What changes: Breaks work into phases, tracks progress, saves checkpoints.
Orchestration
Switch on: --orchestrate
Kicks in when: Jobs that need several tools, or could run in parallel.
What changes: Picks the best tool for each step and runs independent steps together.
Token Efficiency
Switch on: --uc / --token-efficient
Kicks in when: Context more than 75% full, or very large jobs.
What changes: Answers in a compressed, symbol-heavy style that uses 30–50% fewer tokens.
Business Panel
Switch on: /sc:business-panel
Kicks in when: Strategy documents and business plans.
What changes: Simulates a panel of business thinkers discussing, debating or questioning.
If replies suddenly turn terse and full of symbols

That is Token Efficiency mode, which starts automatically when the conversation is over 75% full. It is expected. Start a fresh Claude Code session to reset, or ask Claude to answer normally.

Check your own installation

The mode, rule and flag definitions ship inside the SuperClaude package, but the 4.3.0 installer copies only the command and specialist files into ~/.claude/. Much of the mode behavior is repeated inside individual commands, so it works in practice. If a mode flag seems to be ignored, describe the behavior in words as well.

RuleIn practice

Section 21

Frequently Asked Questions

Short answers to what newcomers ask most.

Is SuperClaude Made by Anthropic?

No. It is an independent open-source project under the MIT license. Anthropic makes Claude Code; it does not support SuperClaude.

Does It Cost Anything?

SuperClaude itself is free. Some helper tools need keys from their providers (Tavily, 21st.dev, Morph), which may have free tiers or charges.

Will It Change My Claude Plan, Model or Bill?

No. It is configuration only. Deeper flags such as --ultrathink do use more tokens on that task, because they do more work.

Do I Need to Know How to Code?

Not for research, business review, explanation or planning commands. For building, you will understand more if you can read code, but the beginner recipes explain each step.

Do I Need All Ten Helper Tools?

No. Every command works without them. Start with Context7 and Sequential; add others when a recipe calls for them.

Is It Safe on an Existing Project?

Look-only and plan-only commands never touch files. The house rules ask for feature branches and commits before risky steps. Still review changes before committing, as with any tool that writes code.

Why Does a Command Stop Instead of Finishing the Job?

Deliberately, so you can review a plan, diagnosis or spec before code changes. Section 5 lists every stopping point.

What Is the Difference Between /sc:pm and /sc:task?

/sc:pm is the coordinator for a whole goal across a session. /sc:task runs one defined job and stops.

Are /implement and /sc:implement Different?

No. The short form appears in some documentation; the installed name is /sc:implement.

Can I Use Only Part of It?

Yes. Use one command and ignore the rest. Nothing depends on using the whole framework.

Where Do Reports and Plans End Up?

In a claudedocs/ folder in your project, for example claudedocs/research_*.md and claudedocs/workflow_*.md.

How Do I Know Which Version I Have?

Run superclaude version in a terminal. This guide covers 4.3.0.

What Is Coming Next?

A TypeScript plugin edition (v5) is in development with no release date. Until then, install with pip or pipx as described here.

Does It Work With Other AI Tools?

This framework targets Claude Code. Sister projects exist for other assistants (SuperGemini, SuperQwen), maintained separately.
